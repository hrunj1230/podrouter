podrouter · Runpod Pod

설정 하나에서 Pod 하나, 주소 하나.

로컬 화면이나 CLI가 YAML을 읽고 Runpod에 Pod를 만듭니다. 뜨면 https://<pod-id>-<포트>.proxy.runpod.net 를 돌려주고, 그 시도가 실패하면 방금 만든 Pod만 지웁니다.

전체 화면의 세 버튼 생성 재시도 up 한 번 누구를 끄나 한도

전체 경로

키는 브라우저로 나가지 않습니다. 페이지는 로컬 서버만 부르고, 서버가 .env의 RUNPOD_API_KEY로 Runpod GraphQL을 부릅니다.

01
브라우저 127.0.0.1 전용 페이지. 재고 표, 띄우기 폼, 이 도구가 만든 Pod 목록.
02
로컬 서버 podrouter web. 다른 주소로 열리면 거절. 생성은 한 번에 하나.
03
podrouter up / down 서버가 임시 YAML을 쓰고 CLI를 한 번 실행합니다. 끝나면 파일을 지웁니다.
04
Runpod api.runpod.io/graphql. 생성은 podFindAndDeployOnDemand.

화면의 세 동작

재고 표의 “자리 있음”은 보여 주기용입니다. 실제 배정은 생성 요청이 결정합니다. 표에 자리가 없어도 생성 버튼은 생성을 시도합니다.

조회

폴링 시작, 재시도 끔

  1. 15–300초, 기본 60초마다 GET /api/gpus
  2. GPU 종류, 가격, 재고만 다시 그립니다
  3. 1달러 미만이고 자리가 없다가 생기면 배너를 띄웁니다
  4. Pod를 만들지 않습니다
한 번

이 설정으로 띄우기

  1. POST /api/launch, 재시도 없음
  2. 헬스 체크를 켜면 /health가 200이 될 때까지 기다립니다
  3. 끄면 Pod id와 주소만 받고 끝냅니다
  4. 자리가 없으면 그 요청은 거기서 끝입니다
반복

재시도 켜고 폴링 시작

  1. 확인창 뒤에 생성 작업을 엽니다
  2. 헬스 대기는 강제로 꺼집니다
  3. 간격은 15초 이상 300초 이하, 횟수는 1–240, 기본은 15초와 240번
  4. 표 갱신은 따로 계속됩니다
  5. 폴링 멈춤은 POST /api/cancel

생성 작업이 도는 순서

작업은 메모리에만 있습니다. 서버를 끄면 진행 중 표시도 사라집니다. 이미 만들어진 Pod는 서버 프로세스와 별개로 Runpod에 남습니다.

검사
키가 비었거나, 이름·이미지·가격·TTL이 형식에 안 맞으면 400

이름과 GPU id, 이미지에 허용된 글자만. TTL은 3h, 30m처럼 읽힙니다. 시간당 가격 상한은 생성을 막지 않습니다.

잠금
이미 생성이 돌고 있으면 “a launch is already running”

잠금은 성공, 실패, 취소 다음에 풀립니다.

시도마다
카탈로그에서 시간당 GPU 가격을 확인한다

가격이 숫자로 확인되면 그 금액으로 생성을 시도합니다. 가격을 모르면 그 GPU는 건너뜁니다. 금액이 크다는 이유만으로 멈추지 않습니다.

실행
임시 YAML을 0600으로 쓰고 podrouter up을 한 번 돌린 뒤 파일을 지움

재시도 경로는 --wait=false라서, 주소가 나오면 그 Pod를 헬스 실패로 지우지 않습니다. 제한 시간은 대기 없음 180초, 헬스 대기 1200초.

갈림
주소가 나오면 성공으로 종료하고 hourly_price를 같이 돌려준다. 마지막 횟수면 “no seat within the attempt limit”

그 외에는 간격만큼 1초씩 자면서 취소를 확인합니다. 취소 문구는 “취소했습니다”.

podrouter up 한 번의 속

설정
YAML을 읽고 ${이름}만 환경변수로 바꿈

비밀이 비어 있으면 만들기 전에 끝냅니다. 해시가 가리키는 것은 치환 전 YAML입니다. 같은 이름이라도 설정이 다르면 다른 Pod입니다.

재사용
이미 살아있는 같은 이름, 같은 해시 Pod가 있으면 주소를 다시 찍고 새로 만들지 않음

표시는 PODROUTER_MANAGED=1 이고 상태가 종료·종료됨·죽음·실패가 아닌 Pod만 해당합니다.

후보
GPU 목록을 위에서 아래로 한 번씩

가격 조회가 재고·영구 오류면 다음 GPU. 가격을 숫자로 확인할 수 없으면 다음 GPU. 가격이 있으면 상한과 관계없이 생성을 시도합니다. 생성이 재고 오류거나 id가 없으면 다음 GPU. id가 돌아오면 그 GPU로 확정하고 아래 후보는 보지 않습니다. 결과에는 hourly_price가 찍힙니다. 화면 폼은 GPU를 하나만 넣습니다.

컨테이너
시작 명령 앞에 TTL 타이머를 붙임

sleep <초> 뒤에 runpodctl remove pod $RUNPOD_POD_ID, 그리고 사용자가 적은 인자. 로컬 프로세스는 이 타이머에 관여하지 않습니다. 이미지에 runpodctl이 없으면 시간 내 자동 종료는 실패할 수 있고, 그때는 down까지 과금이 이어집니다.

남김

성공

--wait=false면 id와 주소를 찍고 끝. --wait=true면 상태가 RUNNING이 된 다음 /health가 200일 때까지 보고, 그다음 주소를 찍습니다. 주소에는 경로를 붙이지 않습니다. 성공한 Pod는 지우지 않습니다.

지움

id가 생긴 뒤의 실패

부팅 시간 초과, 헬스 시간 초과, API 예외, Ctrl+C. 로그 마지막 50줄을 찍고 그 Pod를 종료합니다. 종료 중 추가 Ctrl+C는 무시합니다. 비밀 값은 로그에서 지웁니다. id가 생기기 전의 실패는 지울 Pod가 없습니다.

끄고 목록에 나오는 범위

ls, status, down, 화면의 Pod 표는 같은 조건을 봅니다. 콘솔에서 직접 만든 Pod는 이 목록에 없고, 끄기에도 걸리지 않습니다.

명령하는 일
ls관리 중이고 살아있는 Pod의 id, 이름, 상태, 시간당 가격
status <이름>상태, 시간당 가격, 설정 TTL, 남은 TTL. 남은 시간은 0과 TTL 사이
down <이름>그 이름의 관리 Pod만 종료
down --all이 도구가 만든 살아있는 Pod 전부 종료
화면의 끄기down <이름>과 같습니다

호출을 다시 하는 범위

층다시 하는 조건멈추는 조건
SDK 한 호출 전송 오류, 5xx성 응답, 재고가 아닌 GraphQL 오류. 기본 5번, 0.5초에서 두 배 재고·용량 문구, 인증 오류, 값 오류, Ctrl+C
up의 GPU 목록 위 후보가 가격·재고·id 없음이면 다음 후보 한 번 id를 받았거나, 후보가 끝났거나, 배정 시간이 지남
화면 재시도 한 번 up이 주소 없이 끝나면 15초 이상 쉬고 다음 시도 성공, 취소, 최대 240회

화면이 Runpod에 보내는 생성은 GraphQL입니다. 이 계정 REST 한도로 확인된 값은 분당 180, 시간당 7200, 하루 86400이고, 초과는 429입니다. 15초마다 한 번이면 분당 4회입니다. GraphQL 숫자 한도는 공개돼 있지 않고, Runpod는 2026-10-27부터 GraphQL 제한을 시작한다고 적었습니다.
